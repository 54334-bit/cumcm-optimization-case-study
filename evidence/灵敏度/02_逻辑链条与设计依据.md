# 逻辑链条与设计依据（"灵敏度分析"章节骨架）

> 本文给出**从问题到实验、从实验到结论**的完整推理链，供论文该节直接改写。

---

## 一、为什么必须做这套分析

四问的答案是四个**点估计**。点估计本身不回答两个必然被追问的问题：

1. **模型里那些"不是题面给定、而是我们选定"的量，换一换结论会不会翻？**
   —— 典型是终端库存价值 λ（模型偏好）与电池单程效率 η（物理参数）。
2. **我们赖以决策的信息本身有误差，这个误差值多少钱？外部价格变了，成本变化里有多少是外生的、多少是决策带来的？**
   —— 前者是 Q3 的预报质量，后者是 Q4 的波动电价。

因此灵敏度分析的目标**不是再优化出一个更低的数字**，而是**证明已交付结论的稳健性边界**，
并把"为什么变化"讲清楚。

## 二、三层设计及其互补性

```
┌─ L1 参数层 ────────────────────────────────────────────────┐
│  S0  终端库存价值 λ（元/kWh）   Q2                         │
│  S1  电池单程效率 η             Q1 / Q2 / Q4-2（全年）      │
│                                Q3 / Q4-3（26 日状态冻结筛查）│
│  回答：模型自身参数变动时，结论方向与量级是否稳定。          │
└────────────────────────────────────────────────────────────┘
┌─ L2 信息层 ────────────────────────────────────────────────┐
│  S2  官方预报误差强度 ρ          Q3（离线反事实）            │
│  回答：预报质量变化如何传导到成本、调整量与应急风险。        │
└────────────────────────────────────────────────────────────┘
┌─ L3 机制层 ────────────────────────────────────────────────┐
│  S3  价格环境 × 计划来源 2×2     Q3 / Q4-3                  │
│  回答：成本变化中多少来自价格本身、多少来自重新优化。        │
└────────────────────────────────────────────────────────────┘
```

**三者互补的理由**：L1 改的是"我们选的数"，L2 改的是"我们拿到的信息"，L3 改的是"外部环境"。
三者的扰动源**互不重叠**，因此合起来构成对"参数—信息—环境"完整外生面的覆盖；
任何一条单独都不足以支撑"结论稳健"的论断。

此外，S4（既有消融的统一呈现）回答第四类问题：**"我们的方法里，各部件各值多少钱"**——
预报裕度（Q2）、滚动更新（Q3）、执行器 v2b（Q3）、裕度结构（Q4-2）。

## 三、每条轴的设计依据（为什么这样选）

### 3.1 λ 为什么取 {0, 0.3776, 0.4720, 0.5664}

- `0.4720` 是冻结基准（由早期确定性口径的日界链对偶标定，边际量 `C′(6000)=0.4711`，落在 [0.4424, 0.4802] 内）。
- `0.3776 = 0.8×0.4720`、`0.5664 = 1.2×0.4720` 构成**不使用正式期结果调参**的对称 ±20% 局部扰动。
- `0` 是**结构性极端消融**，检验"完全忽略终端库存价值"的后果，不参与局部弹性拟合。
- 实测给出"**平台—跳变**"结构（§表 A-1）：λ ≤ 0.3776 时段末放空至下界、
  λ ≥ 0.5664 时顶到上界。**因此 λ 轴不报单一弹性，只报分段响应与阈值。**

### 3.2 η 为什么取 {0.85, 0.90, 0.95}

- `0.90` 是冻结基准（**单程**效率；往返 0.81）。
- `0.85 / 0.95` 是围绕基准的**工程压力水平**，用于诊断"效率变化是否改变策略与风险"，
  **不宣称**它是真实设备的统计置信区间。
- 论文中必须写"单程 0.90"，**不得写成"整体效率 90%"**（那对应往返 0.81 的错误读法）。

### 3.3 ρ 为什么取 {0.5, 1.0, 1.5} 且只在 Q3

- 只有 Q3 使用**官方预报（附件3）**，因此它是唯一可以做"预报误差强度"反事实的问题。
- 做法：在**附件3 原生小时节点**上按 `F_raw(ρ) = P_real + ρ·(F − P_real)` 重配，
  再交给**冻结的重构函数**（小时末端采样 + 线性插值 + 非负截断 + slot_end 映射）落到 144 槽。
  ⇒ 检验的是"**整套官方预报系统质量缩放**"，不是只改一个 MAE 统计量。
- **边界披露**：`ρ=0` 只是"原生小时节点 oracle"，仍要经过冻结插值，**槽级误差一般不为 0**；
  因此本轴标记为 **oracle 控制的离线反事实**，不是可部署预测方法，也不是未来信息可用性假设。

### 3.4 为什么所有臂统一"无预热、起点 SOC=6000"

冻结交付件的评价期起点一律是 **2025-02-01 00:00、SOC = 6000 kWh**。
若每个臂各自做 1 月预热，基线臂的起点会漂到 λ 决定的 7,950 kWh，
**它就不可能复现交付值**，整条轴随之作废。
故所有臂**共用同一起点**——这既是复现的前提，也是**最严格的可比性保证**：
轴间差异只能来自被测参数，不会混入初始状态差。

### 3.5 为什么 Q3/Q4-3 的 η 只做 26 日状态冻结

Q3/Q4-3 是滚动 LP（每臂 334 天 ≈ 1,336 次 LP 求解），全年重跑五档代价高。
筛查设计为：取 **2–12 月每月 1 日与 15 日 + 四个题目指定日期 = 26 日**，
每个日期的**日初 SOC 从该问的无预热基线轨迹同日值读取**（实测 104 个 (日,臂) 对全部吻合）。
⇒ 结论**只能表述为"局部机制响应"，不得写成全年稳健性**；若触发升级条件再补全年。

### 3.6 为什么用 `J_cmp` 而不是 `J_cash` 作 λ/η 轴的主判据

λ 与 η 都会**改变期末库存**。λ=0 会让年末 SOC 从 7,950 掉到 1,200，
相当于"把 6,750 kWh 库存花掉换现金"——`J_cash` 因此**变低**，
但按统一尺度 `J_cmp = J_cash + λ_eval(S_start − S_end)` 修正后反而**变高**。
实测两把尺**给出相反结论**（详见 `04` 陷阱 1）。故：
**λ / η 轴以 `J_cmp` 为主、`J_cash` 为辅，并披露"更低是因为放空库存"。**

## 四、跨问怎么读（红线）

| 对照 | 允许的写法 | 禁止的写法 |
|---|---|---|
| Q4-2 vs Q2 | "波动电价使问题二口径的费用上升 4.51%"（**价格区制差异**） | "改进/劣化" |
| Q4-3 vs Q3 | "波动电价使问题三口径的费用上升 4.63%" | 同上 |
| Q2 vs Q3 | **只并列**："两问的信息结构与结算机制不同，费用并列如下" | "Q3 更优"、任何减法 |

原因是：Q2 是**非预见 + take-or-pay**，Q3 是**官方预报 + 滚动 + 承诺—调整结算**，
两者不是同一问题的两个算法，其差值没有"改进"的语义。

## 五、证据链：从合同到结论

```
冻结合同            运行                   门                     结论
──────────  →  ──────────────  →  ──────────────  →  ──────────────
唯一权威文件        每臂一个 run_id       G0 基线复现           表 A/B/C 与结论句
(汇总建模方案)       manifest/result/     G1..G11 各门          (本目录 01)
                     daily/逐槽台账       + 监理独立复算
```

- **单轴可核**：每臂 `config_hash` 唯一；同问内 `raw_input_hash` 唯一；
  只有改预报/价格的臂才变 `derived_input_hash`（机器验证）。
- **物理可核**：**18 条单轨迹臂合计 640,368 个槽**的 SOC 递推残差 ≤1.5e-10 kWh；**4,329 处日界**零断裂；
  `S3_2x2` 另有 4 格 × 48,096 = 192,384 槽的台账（不并入上数）。
- **账本可核**：19 个臂的逐槽台账反算 `J_cash`，最大偏差 3.2e-07 元。
- **结论可核**：每个数字都能沿"表 → 运行产物 → 代码入口"走回去（见 `03`）。
