# 数据清洗策略说明（对话 B）

生成时间：2026-09-10

## 0. 一句话结论

本题**不做“修改原始数值”的数据清洗**（不插补、不剔除、不平滑、不去噪、不归一化）。
只做**结构规整、类型转换、时间对齐、单位换算、只读核验**，全程不改动任何业务数值。
官方给的负载、光伏、电价、预报是“不可改动的外生输入”，直接代入模型。

## 1. 为什么不做值层面清洗

三方一致（本人逐文件盘点 + GPT + 豆包）：

1. 四个附件数值本身干净完整：0 缺失、0 负值、时间/日期网格严格对齐，不存在需要插补或剔除的脏数据。
2. 题面把负载、光伏、电价、预报作为**给定输入参数**，优化的是购电/充放电/弃光变量，不是“修正输入”。
3. 光伏零点（夜间）、电价高低、负载峰谷都有明确物理意义，不是异常值；擅自平滑/截断会改变优化问题本身。
4. 竞赛评阅逻辑：运筹调度题默认输入即题目已知条件，题面未要求预处理时不得改动。

结论表述（论文口径）：
> 对四个附件进行表结构、日期连续性、时间网格、缺失值、重复性、数值类型与基本物理域核验，
> 未发现需要修改原始数值的问题；负载/光伏/电价/预报作为外生给定输入，保留全部原始数值，
> 仅做结构化读取、类型转换、时间对齐、单位换算与模型输入准备。

## 2. 需要做的 6 类“数据准备”（均不改数值）

1. **只读留存**：原始文件、sheet 名、列名、原始单元格值、SHA-256、读取时间、程序版本全部登记。
2. **完整性/结构校验**：行数、列数、日期连续性、时间网格、重复、空值、负值、数值类型逐项核验。
3. **结构归一化**：附件3 日期列空串 `ffill`（恢复合并单元格的归属关系，保留 `日期_raw` 与 `日期_norm` 两列）。
4. **类型与时间标签统一**：日期/时间/数值类型统一；附件1/2/4 时间列按“区间右端点”映射到自然日 144 区间。
5. **单位换算**：功率(kW) × dt(=1/6 h) → 电量(kWh)，保证与购电量/充放电量/储电量同纲。
6. **索引建立**：按“日期+时段”建索引，对齐 result 模板行序。

## 3. 已锁定口径（与 Q1_1.0 一致，以 Q1 方案为准）

- 时间口径主取 **R**：标签为区间右端点。`00:10` → `[00:00,00:10)`，`0:00+1` → `[23:50,24:00)`，全天 144 区间。口径 L 仅作敏感性。
- `dt = 1/6 h`；模型变量统一 kWh。
- 单时段最大充放电量 `Ebar = 5000 * dt = 833.333... kWh`。
- 充放电效率：单边均 0.9，`S_t = S_{t-1} + 0.9*C_t - D_t/0.9`。
- 日初/日末 SOC = 6000 kWh（Q1）；SOC ∈ [1200, 10800] kWh。
- 允许弃光、不允许售电、不设外网购电上限。
- **附件1 电价（固定价）≠ 附件4 电价（实时波动价）**，两套独立口径；Q2/Q3 用附件1，Q4 用附件4。
- 附件3 整点预报 → 10min 网格用**零阶保持（最近邻）**，不插值（避免编造题目未提供的信息）。
- 附件1/2/4 时间列是右端点网格；result 模板首列标签整体偏移 10 分钟，模型第 i 区间 → 模板第 i 数据行，不按错误标签重排。

## 5. 风险点与待拍板项

1. **初始 SOC 衔接**：附录1 给定 2025-01-01 0:00=6000，而 result2/3/4 从 2025-02-01 开始 → 需先递推 1 月储能状态，2/1 0:00 SOC 作为后续初值（Q2–Q4）。
2. **Q1 的 S0=S144 周期约束不能无脑套到 Q2–Q4**，除非论文明确是统一假设。
3. **预测值 vs 实际值**：Q3 决策只用“当时可获得的预报”，附件2 实际光伏只用于事后紧急购电，防信息泄漏。
4. **固定电价 vs 波动电价**：Q2/Q3 用附件1 固定价，Q4 才用附件4。
5. **result 模板“示意/展开”**：result2/3/4 的充放电量/紧急购电量表用 `⁝` 省略号示意，需按 334 天展开（充放电 334×6、紧急 334×3 行）。
6. 附件3 整点→10min 的零阶保持是建模假设，论文需声明。
