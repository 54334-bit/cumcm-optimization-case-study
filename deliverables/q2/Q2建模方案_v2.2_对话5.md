## 2. 符号与参数

| 符号 | 含义 | 取值/来源 |
| --- | --- | --- |
| `T` | 每日区间数 | 144 |
| `dt` | 区间长度 | 1/6 h |
| `p_t` | 区间 t 电价 | 附件1（144 个，逐日重复）：min 0.3713 / max 1.3952 / mean 0.7662 元/kWh |
| `L[d,t]`, `PV[d,t]` | 日 d 区间 t 负载/光伏**功率**（kW） | 附件2 实际值 |
| `Ltilde_k[t]`, `PVtilde_k[t]` | 情景 k 区间 t 的**电量**（kWh）：`Ltilde = L·dt`、`PVtilde = PV·dt` | `dt = 1/6 h` |
| `Ebar` | 单区间最大充/放电量 | `5000·dt = 833.333 kWh` |
| `S` | 储能电量（kWh），定义在区间边界 | `S∈[1200,10800]` |
| `η` | 单边充/放效率 | 0.9 |
| `N` | 情景窗口天数 | 默认 7 |
| `K` | 情景个数 | `min(N, 可用历史天数)` |
| `G_plan[t]` | **决策**：当天计划购电功率（kWh/区间） | here-and-now |
| `C_k,D_k` | 情景 k 的充/放电量（kWh/区间） | recourse |
| `R_PV_k`, `R_G_k` | 情景 k 的弃光伏 / 弃计划购电 | recourse |
| `e_k` | 情景 k 的紧急购电量（计划层视角） | recourse |
| `S_k` | 情景 k 的 SOC 轨迹 | recourse |
| `λ*` | 储能水价值（terminal water value） | 0.4720 元/kWh（§6） |

> **量纲口径（强制）**：`L`、`PV` 是功率（kW）；`G_plan, C, D, e, R_PV, R_G, S` 是**区间电量**（kWh）。所有平衡式、SOC 递推与目标函数一律在 **kWh 口径**下书写——凡出现 `L`/`PV` 必须带 `·dt`。`p_t` 单位为元/kWh，费用单位为元。`dt = 1/6 h`。

SOC 递推（电池侧电量口径）：`S_k[t+1] = S_k[t] + 0.9·C_k[t] − D_k[t]/0.9`。

> **弃电术语（v2.2 统一）**：`R_PV` ＝ **弃光伏**（光伏出力超过可消纳上限的部分）；`R_G` ＝ **弃计划购电富余**（已按计划付费却用不掉的部分，等价于 `G_plan − G_act`）。论文总称一律写"**弃电**"，并注明 `弃电 = R_PV + R_G`；**不得**把 `R_G` 混称为"弃光"。

## 4. 情景构造（SAA，日级经验分布）

对每个评估日 d：

```text
Ω_d = { (L[d−1], PV[d−1]), (L[d−2], PV[d−2]), …, (L[d−N], PV[d−N]) }
```

- **每个情景是一条完整的 144 时段日内曲线**，即"整日联合情景"。
- **禁止分时段独立抽样**：`L`、`PV` 的日内时序与相关性必须整体保留，否则储能的跨时段耦合被破坏，recourse 不可执行（豆包补充第 1 条）。
- 默认 `N=7`；`d−1<0` 时用已有天数（`K=min(N,d)`）。
- 点预报 `mean_N`（同时段均值）**只用于报告与对照**，不作主输入。
- **预测器口径声明（v2.2 收口）**：主线的计划层**输入是上述 7 条整日情景曲线，不是点预报**；文档中若引用点预报，**主线口径 = `mean7`（前 7 天同时段均值）**；**`lag-7` 从未进入本主线**，仅作备选对照（见 `§11`）。实测（全年滚动，kW）：`lag-7` MAE 176.8 、`lag-14` 210.7 、`lag-1` 650.0、`mean7` 781.2——lag-7 精度更高，但**收尾期不改主线**，仅如实记为未采用备选。
- **严禁使用当天及以后的数据**（口径 B）。

## 5. 0:00 计划层模型（两阶段随机 LP / SAA）

**决策变量（v2.2：计费量与物理量分离）**

- here-and-now（144 个，全部情景共享）：`G_plan[t] ≥ 0` —— **计费口径**的计划购电量
- per-scenario recourse 的**实际取电量**：`G_act_k[t] ≥ 0` —— **物理口径**，即电网实际交付给微网的电量
- per-scenario recourse：`C_k[t], D_k[t], R_PV_k[t], e_k[t]`（各 144），`S_k[t]`（145）
- 内部等价变量（不独立参与求解）：`R_G_k[t] := G_plan[t] − G_act_k[t]` —— 计划购电富余（弃电的电网部分）

**约束（对每个情景 k 成立）**

```text
(平衡)     G_act_k[t] + PV_k[t]·dt + D_k[t] + e_k[t] = L_k[t]·dt + C_k[t] + R_PV_k[t]   # 全部 kWh
(取电上限) 0 ≤ G_act_k[t] ≤ G_plan[t]     # 题面：计划购电费按 G_plan 计，实际取电不得超过计划
                                          # 等价写法 R_G_k[t] := G_plan[t] − G_act_k[t] ≥ 0
(弃光上限) 0 ≤ R_PV_k[t] ≤ PV_k[t]·dt
(SOC)      S_k[t+1] = S_k[t] + 0.9·C_k[t] − D_k[t]/0.9
(统一初值) S_k[0] = S_0 = S_exec[d−1,144]  ,  ∀k
(功率)     0 ≤ C_k[t], D_k[t] ≤ Ebar = 833.333
(容量)     1200 ≤ S_k[t] ≤ 10800   # t = 0..T 均含终端时刻 T：终端只是去掉「固定值」约束，不去掉上下限
(非负)     G_plan[t], G_act_k[t], e_k[t] ≥ 0
(终端)     不设硬约束，改由目标中的残值项内生处理
```

> **两套变量的关系（v2.2 收口：裁定为写法 Q）**：计划层**禁用 `R_G`**（即 `G_act_k[t] = G_plan[t]`），承诺购电量在每个情景下**全额进入微网物理平衡**；`R_G` 仅作为**执行层 E1 的富余消纳末档**存在。依据：题面只允许**光伏弃电**，未给出电网侧拒收/卸载装置；`take-or-pay` 只决定**付多少钱**，不决定**电去哪**。实证：允许 `R_G` 时计划层会买到超净需求 ~1030 kWh、充电恰顶 833.33 上限而后丢弃，优化目标低 304.43 元但**真实执行现金反而高 2,700.17 元**（见 §15.9）。

**目标**

```text
min  Σ_t p_t·G_plan[t]  +  (1/K)·Σ_k Σ_t 5·p_t·e_k[t]  −  λ*·(1/K)·Σ_k S_k[T]
```

**关键性质**

- **无储能退化**：`e = (Y−G_plan)^+`，`Y = (L·dt − PV·dt)` 为扣光伏后的剩余净负荷（可正可负）。过购成本 `c_o=p`、欠购成本 `c_u=4p`，临界分位数 `q* = c_u/(c_u+c_o) = 0.8`。
  报童口径必须特别声明三点（GPT + 豆包一致要求）：
  1. **对象**：`G_plan*` 是 `Y` 的 0.8 分位数的**非负截断**，等价于 `(L·dt − PV·dt)^+` 的 0.8 分位数；不得与"原始净负荷分位数"混淆。
  2. **离散分位数定义**：取"最小的 `G` 使 `K` 个情景的经验累积分布 `F_K(G) ≥ 0.8`"（经验下分位数），与两阶段 SAA LP 的最优解一致；离散分位数有多种定义，必须写明。
  3. **边界**：当 `Y` 的 0.8 分位数 `< 0` 时，最优 `G_plan = 0`（计划购电非负），对应光伏完全覆盖负载的极端情景。
- **有储能**：过购电量可入库/跨时段搬运，边际过购成本降为 `p/η` 级别 → `q* > 0.8`。这正是论文可解释"计划购电量 ≠ 预测净负荷"的机制。
- **弃电必须显式拆成两项**：`R_PV`（弃光伏，上限 `PV·dt`）与 `R_G`（弃计划购电富余，上限 `G_plan`，等价于 `G_plan − G_act`）。只要 `G_plan` 按 take-or-pay 全额计费，低负荷 + 高光伏 + 储能已满时就必然出现"已付费但用不掉"的电量，它必须被显式弃置、不能凭空消失（GPT 补充第 2 条）。论文统一用"**弃电**"作总称，不把两项混称为"弃光"（裁定书 §8 修订点 7）。
- **两项弃电的优先级只在执行层生效**：计划层 SAA 中 `R_PV`、`R_G` 都是自由的非负变量，只受各自上限约束（二者的费用系数均为 0，故计划层不预设弃置顺序）；“先弃光伏、再弃计划购电富余”是 §7 执行器 E1 的既定优先级。

**非预见性声明（必须写进论文，GPT + 豆包一致要求）**

`G_plan` 是 here-and-now，对全部情景相同；`C_k/D_k/R_PV_k/R_G_k/e_k/S_k` 是"**情景完全揭示**"下的 recourse，属于**离线计划基准**。三条强制约定：

1. `result2` 中一切运行数据（充放电、SOC、紧急购电）**全部来自 §7 的 E1 在线因果执行**，与计划层 recourse 数值无直接对应关系。
2. 计划层 recourse 只用于求解 `G_plan` 的期望成本最小化；其数值含义是"若当天恰为某一历史情景时的最优离线成本"，**不作为实际结算与性能评估的主指标**。
3. E1 的决策严格基于**当前区间实测 `L/PV` 与当前 SOC**，不含任何未来信息；以"打乱当天 `L/PV` 后 `G_plan` 逐位不变、执行结果变化"作为验证。

**诚实的限度声明**：E1 保证执行可行，但**不能证明** `G_plan` 在因果信息下最优；计划层是"情景完全揭示"的两阶段模型，其最优性只在情景集上成立（GPT 阻断项 3）。

### 5.1 计划—执行闭环的分维度验证（裁定书 §2，取代 v2.1 的单点自查）

**结论先行**：闭环必须在**两个维度**上分开陈述——**时序结构维度闭合；购电水平（整体缩放）维度存在系统缺口，且已量化归因。**

## 6. 终端处理：SOC 残值法（本方案唯一分歧点，已裁定）

### 6.1 裁定

**主线采用终端 SOC 残值法（water value），不用周期硬约束 `S_k[T]=S_k[0]`。**

| 口径 | 形式 | 定位 |
| --- | --- | --- |

1. 终端残值法是**建模假设**，题面未对 Q2 规定 `S_0=S_144`（题面只对 Q1 提）。

## 7. 执行层：E1 —— 无未来信息的**因果启发式**执行器（receive-and-store）

给定已冻结的 `G_plan[·]`、区间前 SOC `S`、当天**实际** `L_act[t], PV_act[t]`：

```text
for t = 0..143:
    gap_t = L_act[t] − PV_act[t] − G_plan[t]        # >0 缺口，<=0 富余
    if gap_t > 0:                                    # 缺口分支
        D_exec[t] = min(Ebar, 0.9·(S − 1200), gap_t)
        H[t]      = gap_t − D_exec[t]                # 紧急购电
        C_exec[t] = 0
    else:                                            # 富余分支
        C_exec[t] = min(Ebar, (10800 − S)/0.9, −gap_t)
        rest      = −gap_t − C_exec[t]               # 仍消纳不掉的富余
        R_PV_exec[t] = min(PV_act[t], rest)          # 先弃光伏
        R_G_exec[t]  = rest − R_PV_exec[t]           # 再弃计划购电富余
    S ← S + 0.9·C_exec[t] − D_exec[t]/0.9
```

- **全额接收 `G_plan`**：take-or-pay 已付费，电网必然足额交付；微网无理由拒收已付费的低价电量。
- 优先级：**供负载 → 充储能 → 弃光伏 → 弃计划购电富余**；缺口时：**先放电 → 不足才紧急购电**。
- 互斥性：同一区间 `H[t]·R_PV_exec[t] = 0`、`H[t]·R_G_exec[t] = 0`。
- 跨日：`S_d[0] = S_exec[d−1,144]`；首日（2025-02-01）日初 SOC = 6000 kWh；**不每日重置**。

**命名与限度（外部意见第 4 条，已采纳）**：E1 **不是**"在线最优执行器"，而是**只依据当前区间实测值与当前 SOC 的因果启发式**。它不看 `p_{t+1}`、不看未来 `PV`，因此有两条已知短视：① 当前看到富余就充满电池，可能挤压随后时段的消纳能力（多弃光/多弃计划电）；② 当前出现缺口就放电，可能提前耗尽电池导致晚峰紧急购电。论文中一律称其为"**因果启发式执行器（causal heuristic）**"，并与 §11 的 Oracle 完美信息下界明确区分。

**两条短视的量化证据（裁定书 §4，取代 v2.1 的纯定性描述）**

| 短视 | 机制 | 量化证据 |
| --- | --- | --- |
| ① "见富余就充" | 当前区间出现富余即优先充电，可能把电池顶到上限，压缩随后时段的消纳能力 → 多弃电 | 全年弃电 `R_PV = 3,318,418 kWh` + `R_G = 1,033,538 kWh`；分解实验显示水平方向 `α* = 1.067 > 1`，即**多买一点反而更省**（弃电置换的 ε 量级收益） |
| ② "见缺口就放" | 当前区间出现缺口即放电，可能提前耗尽电池，导致晚高峰紧急购电 | 全年 **165/334 天**发生紧急购电，平均 **1.066 段/天**、最多 **5 段**，`J_emg = 1,429,354 元`；分解实验（§5.1(3)）显示该短视贡献约**一半**的 8.33% 水平 regret |

> 两条短视**不能**用"在线最优"掩盖：E1 只看 `L_act[t]`、`PV_act[t]` 与当前 SOC，**不看** `p_{t+1}`、不看未来 `PV`，故只能称为 causal heuristic。

## 8. 结算与 result2 物化

**结算（严格按题面）**

```text
J_plan  = Σ_t p_t · G_plan[t]
J_emg   = Σ_t 5·p_t · H[t]
```

### 15.9 `R_G` 口径裁定（写法 Q）与四处文本修订

**（T1）裁定：计划层禁用 `R_G`；`R_G` 只保留在执行层**（依据：题面**只允许光伏弃电**，未给出电网侧拒收/卸载装置；`take-or-pay` 只决定**付多少钱**，不决定**电去哪**）。计划层平衡式写作

```text
G_plan[t] + PV_k[t]·dt + D_k[t] + e_k[t] = L_k[t]·dt + C_k[t] + R_PV_k[t]
```

（等价于 `G_act_k ≤ G_plan[t]`：承诺购电量**全额进入微网物理平衡**，可全额计费。）**支持的实验**：若允许 `R_G`，计划层会买到超净需求 **~1030 kWh**、充电**恰好顶到 833.33 上限**，其余用 `R_G` 丢掉；其**优化目标低 304.43 元**（11,840,284.26 vs 11,840,588.68）而**真实执行现金反而高 2,700.17 元**（15,240,944.45 vs **15,238,244.28**）→ `R_G` 是"买得起丢得掉"的**伪可行域**，不是更宽的可行域。**我们已交付的实现即为写法 Q，数值无需重跑**（两条独立复算复现到 5e-8）。

> **事实补正（对话7 更正）**：计划层的 `R_G` **不是"自由退化方向"，而是强活跃松弛**——独立复算实测全年 `Σ p·R_G = 1,287,475.60 元`、占计划购电成本 **9.8%**、**334/334 天 > 0**；令 `R_G ≡ 0` 使全年费用**下降 2,605 元**（15,241,957 → 15,239,352）。因此裁定的理由是"**它很活跃、必须明确禁止**"，而不是"设 0 不改变目标"。方向不变：**写法 Q**。


**（T5）e–C 互斥的表述（必改）**：实测全年 **334/334 天计划层 `e ≡ 0`**，互斥二元从未激活（单日 `node=1`、`gap=0`，预解即降为 LP）。因此：

### 15.10 目标函数的精确定义（闭合请神拦阻项）

> **请神 GPT（交付包终审）拦阻项**：`J_obj` 的**精确表达式与单位未闭合**、且与 `J_cash` 的差额来源未给出分解（直接乘积 `λ·S_end ≈ 3,650 元` 与实测差额不符）。下文给出**闭合式与逐项分解**。

```text
J_plan = Σ_d Σ_t p_t · G_plan[d,t]                                   # 计划购电费（take-or-pay，按计划量计费）
J_emg  = Σ_d Σ_t 5 · p_t · H[d,t]                                    # 执行层紧急购电费（5 倍当时电价）
J_cash = J_plan + J_emg                                              # 对外报账"实际现金费用"（**不含**终端残值）

J_obj  = Σ_d [ Σ_t p_t·G_plan[d,t] + (1/K) Σ_k Σ_t 5·p_t·e_k[d,t] ]  # 计划层优化目标（单位：元）
         − λ · (1/K) · Σ_d Σ_k S_k[d,144]                            # 终端残值项（逐日 × 逐情景 累加）
```

- `λ = 0.4720 元/kWh` 是**边际量**（状态价值函数在 `s = 6000` 处的一阶导数），在目标中以 `λ/K` 乘入**每个情景的日末 SOC**，再对**全年 334 天**求和；
- 全年 `e ≡ 0`（e–C 互斥从未激活）⇒ 计划层现金代理 = `J_plan`，故
  `ΣJ_obj = 13,132,150.73 − 终端项全年合计 = 11,840,588.68` ⟹ **终端项全年合计 = 1,291,562.05 元**；
- 对应 `(1/K)·Σ_d Σ_k S_k[d,144] = 1,291,562.05 / 0.4720 = 2,736,360 kWh`（日均情景均值 **8,192.7 kWh**）； **对象必须分清**：8,192.7 kWh/日 是 **S1 主线计划层的情景均值末端 SOC**（全年 2,736,360.27 kWh）；它与（i）**执行层 `s1` 全年合 2,736,890.07 kWh**（+0.019%）、（ii）**独立 LP 重解 2,751,434.82 kWh**（+0.55%，口径不同）**均不相等**；逐日对照与口径说明见 `output/q2_term_soc.json`；其中 `delivered_solution.sum_S_mean_delivered = 2,736,360.273176`（逐日 `per_day[*].S_mean_delivered`）**即交付解本体的值**，由冻结台账恒等式反解（`(J_plan[d] − obj[d]) / λ`），可由第三方**仅凭台账复算**，脚本 `code/q2_term_delivered.py`（带台账 sha256 校验）。
  独立抽样复核（10 天）得日均 **8,246.8 kWh**、外推 1,300,098 元（**+0.66%**，该 0.66% 属**抽样误差**（非退化带宽：10 天样本的日均情景均值在 7,890–9,480 kWh 间波动，均值标准误差 ≈ 2%））；
- **`J_obj = J_cash − λ·S_end` 不成立**：**严禁**写作 `J_obj = J_cash − λ·S_end`（右式 = 15,234,594.28）——终端项是逐日×逐情景累加，非执行层单点 `S_end`。差额分解为：
  - **3,394,005.60 = `J_emg` 2,106,093.55（占 62.05%）+ `λ·(X−S_end)` 1,287,912.05（占 37.95%）**；前者：目标里的应急项用精景 recourse `e`（全年 ≡ 0），而 `J_cash` 用执行层实际 `H`；后者：终端项是逐日×逐情景累加。**不得**把整额挂给终端项。
- 论文写法：正文报 `J_cash`（评委可复核的现金口径），`J_obj` **只出现在模型与求解章节**，并附上式与 λ 的量纲说明。
