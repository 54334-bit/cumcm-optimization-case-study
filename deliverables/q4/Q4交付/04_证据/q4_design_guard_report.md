### S2. Q4-3 的“只读复用、不复制改写”路径与逐日价格 API 不兼容

证据：

- Q4 方案要求只读复用 `q3_main_v2.py + q3_solver_billingC.py + q3_pv_interp.py + q3_data_io.py`，把价格张量换成 `p4[d]`，且“不复制改写其源码”：`Q4最终方案_v3_定稿.md:74-75`。
- 但 Q3 主管线的 `price` 是单条 `(144,)` 向量，逐日固定：`7.5对话\code\q3_main_v2.py:249`（`price : (144,)`）、`:308`（`solve_epoch(..., price, ...)`）、`:365`（`BILLING[...](..., price, ...)`）。
- `run_year_v2()` 把同一个 `price` 传给全年每一天：`7.5对话\code\q3_main_v2.py:399-435`。它没有 `p4[day]` 的接口，也没有价格回调参数。
- Q4 方案列出的复用文件还漏了 `q3_main_v2.py` 直接 import 的 `q3_demand_quantile.py`、`q3_solver.py` 等：`7.5对话\code\q3_main_v2.py:52-64`。

影响：按方案字面执行，无法在“不复制、不修改 Q3 源码”的约束下实现 `p4[d]` 逐日变化。若直接复制 Q3 年度循环到 Q4，又会违反“不复制改写其源码”；这是一个前置设计矛盾。

最小动作：

1. 在 `8对话\code` 写一个薄封装，逐日调用 Q3 的 `run_day_v2`，传入 `price=data_p4[d]`，并由 Q4 自己维护 SOC 接力和汇总；封装中不得重写 Q3 的求解/执行/报账逻辑。
2. 若不接受薄封装，则必须在方案中明确允许“源码快照复制”，并给出快照哈希、与 Q3 v3 的差异清单和一元回归（附件 1 价下必须复现 Q3）。
3. 复用清单补齐全部 transitive imports，并记录哈希。

### S3. G3 断言包存在两个会“误报通过”的缺口

证据：

- `build_assertions()`：`8对话\code\q4_det_seq.py:262-305`。
- C/D 上界只在执行分支中由构造保证：`q4_det_seq.py:144-151`；断言⑦只检查 `χ`：`:296-298`。
- SOC 递推残差计算于：`q4_det_seq.py:213-214`；A④ 的实际 `ok` 只看 `worst_bal_resid`：`:283-286`。
- 质量平衡 A④ 的判据字符串却写了“且 SOC 递推一致”：`:285-286`。

影响：

- `0≤C,D≤833.333` 没有独立 G3 `pass` 项；如果未来换执行器或求解器，可能越界却仍然“8 条断言全过”。
- SOC 递推残差非零时，A④ 仍可能显示 `PASS`，出现“断言文字与判定逻辑不一致”的假通过。

最小动作：

1. 新增 `C/D` 上下界断言：`max(0,-C.min(),-D.min(),C.max()-EBAR,D.max()-EBAR) ≤ 1e-9`；
2. A④ 改为 `worst_bal_resid ≤1e-6 and worst_soc_recursion_resid ≤1e-6`；
3. 重跑闸门与主跑，把新断言写入 `q4_cp2_gate.json` / `q4_cp2_checkpoint.json`。

### S4. Q4-2 缺少“不得用当天实际光伏做计划”的自动泄漏断言

- 当前实现本身是干净的：`q4_det_seq.py:176-184` 的计划输入只使用 `P[d-4..d-1]`；`L[d]` 按 Q2 冻结口径视为已知；`P[d]` 到执行/结算才出现：`:198-202`。

- Q4 的 `build_assertions()`（`q4_det_seq.py:262-305`）没有同类检查，checkpoint 也没有 `leak_check` 字段。

影响：任务书明确要求“不得用当天实际光伏做计划”。当前只能靠人工阅读确认，一旦后续修改把 `P[d]` 引入计划路径，现有 G3 抓不到。

最小动作：

新增 Q4-2 泄漏断言：任选若干天，构造 `P' = P.copy(); P'[d] += 扰动`（并可同时扰动 `P[d]` 为 0 或极大值），重跑同一天计划，断言 `G` 逐位不变、`margin_d` 不变；把结果写入 checkpoint 的 `leakage_check`。

判断：这继承了 Q2 的 take-or-pay/承诺购电语义，不一定是错误；但 Q4 方案 §1.1 只写“富余只能充电→弃光”，没有明确“弃计划购电仍照付”。若不披露，评审可能质疑“为什么弃了还计费”。

最小动作：

1. 在交付说明与方案中写明：计划购电量为承诺量，执行层 `R_G` 为物理未消纳量，现金仍按 `p·G` 结算；
2. 在 annual/checkpoint 增加 `Q_RG` 与 `Σp4·R_G` 诊断；
3. 如果题面意图不是 take-or-pay，需回 Q2 口径重裁，不能只在 Q4 静默改账。

### M3. 物化脚本与求解脚本的附件 4 价格来源不同

问题：

- 求解/评估读取 `B对话\clean\attachment4_clean.csv`：`q4_det_seq.py:84`。
- 物化读取原始 `赛题\...\附件4.xlsx`：`q4_materialize.py:61-70`，并在 `:119` 用它写第 147 列费用。
- 质量监理已验证当前两者逐格相同，但代码中没有“原始 = clean”的运行时断言；未来任一侧更新会造成表 1 费用与 checkpoint 结算价不同源。

最小动作：物化脚本改读同一 `attachment4_clean.csv`，或在 `q4_materialize.py` 入口增加原始与 clean 的逐元素最大差断言，不通过即拒绝物化。

### M4. G2 的“375 段完全相等”未纳入自动闸门

问题：

- `q4_det_seq.py:308-339` 的 `make_gate()` 只检查费用、紧急天数、QH、年末 SOC，没有紧急段数。
- 段数证据由另一个脚本重跑生成：`q4_gate_segments.py:62-105`；它复制了一整套逐日求解/执行逻辑。
- `q4_cp2_gate.json` 因此不能单独证明“375 段完全相等”，必须依赖外挂脚本和人工引用。

最小动作：在 `run_chain()` 的 `agg` 中增加 `n_emg_segments`，把它写入 checkpoint 与 `make_gate()`；`q4_gate_segments.py` 保留作独立交叉验证，而不是作为唯一来源。

### M5. 独立校验器读取 checkpoint，削弱“只读 xlsx + 附件”的独立性

问题：

- 方案 G6 要求“校验器不得 import 任何 `q4_*` 求解代码；只读 xlsx + 附件”（`Q4最终方案_v3_定稿.md:118`）。
- `q4_validator.py` 没有 import 求解器（其 `:12-13` 自述为真），但把 checkpoint 作为列映射抽检和参考对账源：`:481-508,573`。
- 数值主检查仍是独立复算，但 `C5_column_mapping` 的 `pass` 依赖 checkpoint 样本。

最小动作：把 `C5` 标为非独立性检查，或改为纯 xlsx 自检（列 2 vs 列 145 的日期/总量一致性、模板列头与位置映射声明）；checkpoint 只放参考对账附录，不进入 `errors` 判定。

### M6. 读法 C 的 LP 目标与现金公式等价性应写清

问题：

- Q4 方案 `:80-83` 按现金读法列出“下调 0.5p / 上调 1.5p / 紧急 5p”。
- `q3_solver_billingC.py:168-170` 的 LP 目标实际给 `Gm` 和 `Gp` 都用了 `0.5p`，因为读法 C 现金等价于 `p·A + 0.5p|A−G⁰| + 5p·H`；报账函数 `cash_C` 仍按 `:350-352` 计算。
- 两者当前数学等价，但如果 coder 照方案的现金公式直接在 LP 目标里写 `1.5p`，最优解会变。

最小动作：在 Q4 方案 §3 明确写出等价 LP 目标：

`Σ p4·A + 0.5·p4·|A−G⁰| + Σ 5·p4·H − λ_T·S₁₄₄`，

并说明现金报账仍按读法 C 的三段式输出。

## 4. 优化建议

1. **给 Q4-2 checkpoint 加价格来源标签**：`caliber_price="p4"`、`baseline_price="attachment1"`，并增加 `mixing_count=0` 的显式字段，方便第三方一眼判定 G7。
2. **把全部 145 点 SOC 路径或每日 `S_min/S_max` 落盘**：当前 `q4_cp2_checkpoint.json` 只存每天的 `S0/S1`，`soc_min/soc_max` 是运行汇总；独立复算虽能重建，但第三方不能直接从 checkpoint 做逐点核验。
3. **修正闸门 QH 判据**：质量监理已指出正确写法应为 `expected=55,801.05`、`tol=0.01`；建议在下一次重跑时修正，而不是长期保留旧 JSON 作“原样证据”。
4. **增加前视断言**：对 `q4_probe_price_caliber_v2.py` 的三个历史对照臂自动检查所有取数索引 `< d`，避免未来改成滚动均值时把当天数据带进来。
5. **Q4-3 先做一元回归再换价**：在附件 1 价格下，Q4-3 薄封装应与 Q3 v3 的 `result3` 逐指标一致；通过后再用 `p4[d]` 主跑。这样能把“管线复制错误”和“价格变化”分离。
6. **首日裕度窗口注明**：`causal_margin()` 在 `d=31` 时实际用 `tau=4..30`（27 天），不是严格 28 天；Q2 同样如此，属继承边界效应。建议在注释/交付说明中注明，避免第三方按 28 天复算时误判。
