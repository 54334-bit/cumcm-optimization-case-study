### 5. 可行域闭式 vs 逐点枚举

### 需要改进

1. **`q1_dp_verify.json` 中 `resolution_scan["0.5"]` 的斜率三项与 `resolution_scan["1.0"]` 逐位相同**（slope_left −0.47544444444793044、slope_right −0.4754444444406545、slope_center −0.47544444444429246）。
   我实算 δ=0.5 时左/右/中心差商**都**是 −0.4754444444406545。判定：该分块疑似把差分步长硬编码为 1.0，或直接复用了 δ=1.0 的结果。
   影响：绝对差 ~3.8e-12（相对 ~8e-12），**不影响"配对行 288"的结论**，但 JSON 自述的 slope_* 与同块 `delta` 字段不自洽，复算者会把它当矛盾点。
   建议：统一写成 `(V(s+δ) − V(s−δ)) / (2δ)`，并在 JSON 里额外记录实际使用的 Δs。

2. **`q1_dp_verify.json` 的 `feasibility_interval_check` 全部 9 行都是 `analytic = bruteforce = [−1.5, 1.5]`，与 t 无关**。
   我独立算出的真区间随 t 变化（t=0 → [−637.0086, 750]；t=60 → [−925.9259, 750]；t=120 → [−793.0045, 750]；t=143 → [−637.9122, 750]，单位 kWh），量纲和数值都对不上。
   影响：该字段**不可复现**，不能作为"可行域没多算"的证据；并且其 `note` 把结论外链到 `q1_feas.py`（"完整 30 组扫描见 q1_feas.py（ALL_MATCH=True）"），审核者仅凭 JSON 无法验证（且本轮被要求不得读该脚本）。
   建议：把 30 组真实数值（或至少前述 20 组）写进 JSON 并注明单位 kWh；若 [−1.5, 1.5] 是某种归一化，必须写清归一化因子。

3. **精度口径混用**：`q1_value_layer.json` 的 `gap_marginal_value_S0_minus_shadow_price_ST = 0.0043333333342161495` 实际等于 h=1 的中心差分（= −`joint_perturbation.dJ_dh`），而不是两条对偶之差。
   精确对偶差为 `0.47544444444444445 − 0.4711111111111111 = 0.004333333333333356`（与被审 `joint_perturbation.dual_sum` 一致）。
   影响：两者相对差 2.0e-10，都四舍五入到 0.004333，对外结论（"与 5 对话 C'(6000)=0.00433 交叉对照"）不受影响；但同一文件里 `gap` 与 `dual_sum` 用了不同定义，容易被判为不一致。
   建议：`gap` 一律用对偶之差，差分结果单独命名（如 `gap_from_central_diff_h1`）。

4. **V_0(6000) 的性质建议显式标注**：被审文件已给出 rel_err（δ=0.5 → 6.54e-5），这点做得对；但建议同时注明 DP 是 LP 的**上界近似**（我实测 DP − LP 恒为 +2.298 元，见第 4 条表格），避免读者把 35129.25 当作一个新的"最优成本"引用。
